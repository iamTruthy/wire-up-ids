Evasion study: feature-space adversarial perturbation of PortScan flows
=======================================================================
Target: 1000 Friday PortScan flows the model correctly detects (baseline
detection 0.9997). Goal: flip model verdict from ATTACK to BENIGN.

Strategy 1 - single-feature zeroing
  Zeroing any one top-10 feature: flip rate 0.0000 to 0.0010.
  The Random Forest is robust to single-feature evasion. Trees split on
  different features, so knocking out one lets others compensate.

Strategy 2 - greedy top-K zeroing (crude, not realistic)
  Flat through k=8, then k=9 -> 0.042, k=10 -> 0.598.
  Zeroing is not a realizable perturbation. A flow with zero packet sizes
  is physically impossible, so a flip here is partly an off-manifold
  artifact, not achievable evasion. This number overstates fragility in one
  sense (impossible input) and understates it in another (wrong direction).

Strategy 3 - realistic padding toward benign medians (the honest number)
  Only increases values, simulating packet padding an attacker can actually do.
    pad 1 size feature   -> 0.0000
    pad 2                 -> 0.0010
    pad 3                 -> 0.0020
    pad 4 (+Packet Length Std)    -> 0.4280
    pad 5 (+Avg Bwd Segment Size) -> 0.8660
    pad 6                 -> 0.9320
    pad 7                 -> 0.9320
  Padding 5-6 packet-size features toward benign-typical values hides ~93%
  of port scans. Padding beats zeroing because it lands flows in a region
  dense with real benign examples rather than an anomalous empty corner.

Fragility conclusion
  The model resists naive single-feature evasion but is highly fragile to
  realistic multi-feature padding. ~93% of a detected port scan can be
  hidden by inflating packet-size statistics toward benign values.

Realizability caveat
  Some padded features (Packet Length Std, Avg Bwd Segment Size) are
  statistically derived from actual packet sizes and cannot be set
  independently. True achievable evasion is bounded by which features move
  together when real packets are padded, so 93% is an upper estimate. The
  direction of the result, that padding easily evades, is robust.
